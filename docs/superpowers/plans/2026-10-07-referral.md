# Referral / Member-Get-Member Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let members grow the cooperative via a referral code; the referrer earns a reward (wallet / bank / airtime) when the referred member makes their first qualifying contribution.

**Architecture:** A `Referral` model (one per referred member) + per-coop config. The join flow captures the referrer's code; the first qualifying contribution qualifies the referral and pays the reward (wallet credit, bank payout, or a gated VTU airtime adapter). Member + admin commands report and configure.

**Tech Stack:** TypeScript (ESM `.js`), Fastify 5, Prisma 6, vitest 3, SQLite/Postgres.

**Spec:** `docs/superpowers/specs/2026-10-07-referral-design.md`

## Global Constraints

- Money is integer kobo; format with `formatBalance`; parse user input with `parseNaira`.
- `.js` import extensions; no Prisma `enum` (use `String` + comments).
- `prisma/schema.prisma` and `prisma/schema.local.prisma` must stay identical (enforced by `tests/schema-sync.test.ts`).
- Every new table with `cooperativeId` needs a Stage-1 RLS migration + a FORCE-list entry in `prisma/rls/recommended_policies.sql`.
- Coop-scoped writes go through `withTx` + `setCoopContext`; system jobs use `forEachCoop`.
- Every reward/qualification action calls `audit()` with a human-readable description.
- Reward is paid ONCE per referred member; the reward type + amount are snapshotted at qualification.
- Airtime is GATED behind a VTU provider adapter until configured.
- Verification per task: `npm run typecheck` clean · `npm run lint` 0 errors · targeted tests green · full suite green (`npm test`) · schema-sync green.

- [ ] **Step 1: Add the model to both schemas**

Add to `prisma/schema.prisma` (and identically to `prisma/schema.local.prisma`):

```prisma
// A member-get-member referral. One row per referred member (unique), created at
// join and qualified on the referred member's first contribution.
model Referral {
  id               String    @id @default(cuid())
  cooperativeId    String
  cooperative      Cooperative @relation(fields: [cooperativeId], references: [id], onDelete: Cascade)
  referrerId       String
  referrer         Member    @relation("Referrer", fields: [referrerId], references: [id], onDelete: Cascade)
  referredMemberId String    @unique
  referredMember   Member    @relation("ReferredMember", fields: [referredMemberId], references: [id], onDelete: Cascade)
  code             String // the referrer's code used
  status           String    @default("pending") // pending | qualified | rewarded | rejected
  qualifiedAt      DateTime?
  rewardType       String? // wallet | bank | airtime (snapshot at qualification)
  rewardAmount     Int? // kobo (snapshot at qualification)
  rewardedAt       DateTime?
  createdAt        DateTime  @default(now())

  @@index([cooperativeId, referrerId])
  @@index([cooperativeId, status])
}
```

Add relations on `Member` (`referralsMade Referral[] @relation("Referrer")`, `referralReceived Referral? @relation("ReferredMember")`) and `Cooperative` (`referrals Referral[]`). Add to `CooperativeConfig`:
```prisma
  referralEnabled      Boolean @default(false)
  referralRewardType   String  @default("wallet") // wallet | bank | airtime
  referralRewardAmount Int     @default(50000) // kobo = ₦500
  referralMaxRewards   Int     @default(0) // cap per referrer; 0 = unlimited
```

- [ ] **Step 2: Implement `src/services/referrals.ts`**

```ts
// VTU adapter (gated):
export interface VtuProvider { name: string; recharge(params: { phone: string; amount: number; reference: string }): Promise<{ ok: boolean; providerRef?: string; error?: string }>; }
export function resolveVtuProvider(): VtuProvider | null; // null until configured
```

- [ ] **Step 1: Write failing tests**

- `payReferralReward` for `rewardType: "wallet"` credits the referrer's wallet (journal `expense:referral_reward` / `member_wallet:<referrer>`), marks the referral `rewarded`, and audits.
- For `rewardType: "bank"`, it pays the referrer's saved bank account via the existing payout path.
- For `rewardType: "airtime"` with no VTU provider configured, it returns "not enabled" and leaves the referral `qualified` (not `rewarded`).
- A second `payReferralReward` is a no-op (idempotent).

Run: `npx vitest run tests/referral.test.ts`
Expected: FAIL.

- [ ] **Step 2: Implement the reward + VTU adapter**

In `referrals.ts`, `payReferralReward` dispatches on `rewardType`: `wallet` → balanced journal + wallet increment; `bank` → the existing payout path (read `src/services/disbursements.ts`/`payanyone.ts`); `airtime` → `resolveVtuProvider()` (null → gated message). Mark `rewarded` + `rewardedAt` on success; audit `referral.rewarded`. In `payments/vtu.ts`, define the `VtuProvider` interface + a `resolveVtuProvider()` that returns null until a provider is configured (env-gated).
