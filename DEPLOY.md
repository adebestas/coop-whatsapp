# Live Deployment — Render + PostgreSQL + GitHub

The bot is a long-running Node service with a PostgreSQL database, deployed
from GitHub. `render.yaml` in this repo is a Render Blueprint: it creates the
database and web service with the right build/start commands automatically.

> ⚠️ Use the **Starter** plan for the web service. The free plan sleeps after
> 15 minutes of inactivity — WhatsApp messages and scheduled jobs (digest,
> poller, backups) would silently stop.

---

## Step 1 — GitHub

1. Create an **empty private repo** on github.com (e.g. `coop-whatsapp`).
   Do NOT initialize with README.
2. From the project folder:

```bash
git remote add origin https://github.com/<your-username>/coop-whatsapp.git
git push -u origin main
```

Every future `git push` to `main` auto-deploys to Render.

## Step 2 — Render Blueprint deploy

1. Sign up at render.com → Dashboard → **New +** → **Blueprint**.
2. Select the GitHub repo — Render reads `render.yaml` and creates:
   - `coop-db` (PostgreSQL)
   - `coop-bot` (Node web service, health check `/health`)
3. First build fails on missing secrets — that's expected. Open the
   `coop-bot` service → **Environment** and fill in every variable marked
   `sync: false`:
   - `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_VERIFY_TOKEN` (Meta dashboard)
   - `TELEGRAM_BOT_TOKEN` (@BotFather)
   - `MONNIFY_API_KEY`, `MONNIFY_SECRET_KEY`, `MONNIFY_CONTRACT_CODE`,
     `MONNIFY_BASE_URL` (sandbox first), `PAYSTACK_SECRET_KEY`
   - `PILOT_FLOAT_CAP` — your monthly safety ceiling
   - `ADMIN_JWT_SECRET` / `SESSION_SECRET` are auto-generated by the blueprint.
4. **Manual Deploy → Deploy latest commit.** Build passes, schema syncs via
   `prisma db push` (pre-deploy command), bot boots after env validation.

Local development now also needs Postgres — put a free cloud URL
(neon.tech or the Render DB's *External Database URL*) in `.env`.

## Step 3 — Point provider webhooks

Base URL: `https://<render-service-url>` (shown on the service page).

| Provider | Webhook URL | Where to set it |
|---|---|---|
| Meta WhatsApp | `https://…/webhook/whatsapp` | Meta App → WhatsApp → Configuration (+ verify token) |
| Monnify | `https://…/webhooks/monnify` | Monnify dashboard → Settings → Webhooks |
| Paystack | `https://…/webhooks/paystack` | Paystack dashboard → Settings → API Keys & Webhooks |

Also IP-allowlist your Render outbound IP in Monnify/Paystack dashboards if
the provider supports it (Render static IPs require a paid add-on).

## Step 4 — Smoke test with real (small) money

1. Send "menu" to the bot from WhatsApp → menu replies.
2. Register the cooperative + members; every admin runs `enable2fa`.
3. Top up ₦100 via bank transfer to the member's virtual account → wallet
   credits within seconds (webhook path).
4. Super runs `payout 50 <phone> <narration> <totp code>` → money lands;
   poller log shows no stuck transfers.
5. Wait for the 20:00 **Daily summary** message; run `backup` and `reconcile`.

## Notes & limits

- **Backups**: the daily JSON snapshot writes to the service's local disk,
  which resets on redeploys. Your primary safety net is Render's automatic
  Postgres backups (dashboard → coop-db → Backups). Download one occasionally.
- **Exports**: generated files live on the same ephemeral disk — download them
  promptly, or attach a Render persistent disk / S3 later.
- **Scaling**: one instance only (in-memory rate-limit/dedupe maps assume it).
- **Migrations**: `prisma db push` keeps the live schema in sync on every
  deploy; it never drops data without asking (it errors instead).
