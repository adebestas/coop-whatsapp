## 1. Verdict

| `tsc --noEmit` | PASS (exit 0) | |

| `vitest run` | FAIL (exit 1) | 67 failed / 67 passed (134 tests, 15 files, 82.8 s) |

| Prod `GET /health` | 503 `{"db":true,"redis":false}` | known Redis-down quirk; DB reachable |

**Two critical findings, both in shipped code on `main`:**

1. **`main` is not deployable to production.** `prisma/schema.prisma` was switched from `postgresql` to `sqlite` in `00025f8`, and the migration history was replaced with a SQLite-dialect one. Prod runs Neon Postgres. Any fresh deploy of `main` will fail at Prisma client construction (a `postgres://` URL against a `sqlite` provider is a hard validation error). Prod currently answering `db:true` means Render is almost certainly still serving the previous build (`47ef2f6`), or a deploy failed and the last good one is live. **Verify in Render → Events before anything else.**
2. **New cooperative founders and bulk-imported members are silently locked out of the bot.** `conversation.ts:257` drops every inbound message (except the literal word `optin`) from any member whose `consentAt` is null, with no reply. Three code paths create members with `consentAt` null and never route them through the opt-in prompt: the founding superadmin (`handlers/session.ts:1033`), bulk import (`bulk-import.ts:114`), and `seed.ts`. The registration success message literally says "Reply *menu* to see all admin commands" — and `menu` is then ignored. This is also the root cause of ~50 of the 67 failing tests.

## 4. Diagnosis — ranked findings

### CRITICAL

**C1. Schema/migration provider flipped to SQLite on `main` — prod is Postgres**
- `prisma/schema.prisma:` `provider = "sqlite"` (was `postgresql` at `47ef2f6`).
- `prisma/migrations/migration_lock.toml`: `provider = "sqlite"`. All previous Postgres migrations deleted; the single remaining migration `20260918134237_add_guarantor_verification/migration.sql` is SQLite dialect (128× `DATETIME`).
- `Dockerfile:66` CMD still runs `npx prisma migrate deploy` → would fail with a provider mismatch against Neon; `render.yaml` says `runtime: node` / `startCommand: npm start` (comment admits the service "actually deploys via Docker"). Either way the client cannot open a `postgres://` URL with a `sqlite` provider.
- `.env` locally now has `DATABASE_URL="file:./dev.db"` and `DATABASE_PROVIDER=sqlite` (the Neon line was removed). `DATABASE_PROVIDER` is read by nothing in `src/`.
- Impact: any redeploy of `main` takes prod down; if someone "fixes" the boot by pointing `DATABASE_URL` at a file, prod silently becomes an ephemeral SQLite that is wiped on every restart — for a ledger.
- Earlier known issue (migration drift / baselining, memory 2026-09-16) was not fixed; it was replaced with a different, worse drift.

**C2. Silent lockout of members with `consentAt = null`**
- Gate: `src/services/conversation.ts:257-259` — `if (member && member.consentAt === null && preCmd !== "optin") return;` with no reply.
- Paths that create members without `consentAt` and never enter the `awaiting_optin` state:
  - `src/services/handlers/session.ts:1033-1068` — cooperative registration creates the superadmin, sets session idle, tells them to reply `menu`/`setpin`. Both are then dropped.
  - `src/services/bulk-import.ts:114-123` — dashboard CSV/Excel import. Every imported member is a ghost until they guess `optin`.
  - `src/seed.ts:42`.
- The `join` path is fine: `session.ts:532` → `awaiting_optin` → YES sets `consentAt` (`:890`); NO sets `optedOut` and tells them how to re-enable.
- User-visible: founder creates coop → texts `menu` → nothing. Bulk-imported members text `save 2000` → nothing. No log, no reply, no audit entry.
- Also conflates two consents: "receive marketing/alerts" vs "allowed to transact". Replying NO to message consent currently blocks `save`/`balance`/`loan` too.

### HIGH

**H1. Test suite is 50% red and was committed that way** (see 2.2). Money paths — loans, disbursements, withdrawals, deductions, guarantors — currently have zero passing coverage. Fixing C2's helper gap (`consentAt` in each test file's `makeMember`) should flip ~50 tests; RLS tests need a Postgres runner (or a `describe.skipIf(sqlite)`); `prelaunch.test.ts:416` needs `DATABASE_URL` in its fixture.

**H2. Repo hygiene / data-in-git**
- `00025f8` is a 180-file commit that adds ~105 scratch files to the tracked tree: `debug-loan*.ts` (18), `test-*.txt` run logs (~85, several >500 KB), `check-db.cjs`, `fix-imports.js`, `remove-tier.js`, and **14 database backup JSONs under `backups/`**.
- Inspected `backups/coop-backup-2026-09-18T07-31-49-774Z.json`: 1 coop, 6 members, names `Member 5678` style, no money rows → synthetic test data, **no real PII leaked**. But `backups/` is not in `.gitignore` (`git check-ignore` negative), and `index.ts:181` runs `runBackup()` on every boot, so the next local run with real data will stage a real backup for commit.
- `.gitignore` also doesn't cover `test-*.txt` or `debug-*.ts`.

**H3. Redis down in prod** (`/health` → `redis:false`). Rate limits, OTP caps, token blacklist and BullMQ workers (`initQueueProcessors` is a no-op without Redis) are all off in production. Previously known; still true.

### MEDIUM

**M1. Daily digest dedupe is in-memory and local-TZ** — `scheduler.ts:228-239`. `digestLastSentDate` is a `Map`; a restart inside `DIGEST_HOUR` re-sends every super the full debit digest. `now.getHours()` is container-local (UTC on Render) so `DIGEST_HOUR=20` fires at 21:00 WAT.

**M2. Ambiguous-phone lockout UX** (carried from 2026-09-16 finding). `getMemberByPhone(phone)` unscoped returns `null` when a phone belongs to 2+ coops; the person is treated as a guest with no coop-selection flow. Fail-closed (no cross-coop leak) but a double-registered member cannot use the bot.

**M3. Backup loop has no overlap guard** (`index.ts:182-188`); reconcile and poller loops likewise. Low risk at 24 h cadence; the poller at a short `TRANSFER_POLL_MINUTES` could stack if a provider call hangs past the interval.

**M4. `payments/*` adapters are `any`-typed end to end** (30 of the 63 warnings). Provider response shape changes (Monnify/Paystack) will not be caught at compile time; they will surface as runtime `undefined` in payout paths.

### LOW

- `exports.ts:3` dead import; `session.ts:211` destructure-to-omit trio (lint errors).
- `render.yaml` comments contradict themselves about Docker vs node runtime; `DEPLOY.md` grew by 227 lines in the same commit — needs a consistency pass once C1 is decided.
- `src/index.ts` sleeps 500 ms and then checks `isRedisConnected()`; a slow Redis handshake is logged as "not connected" even when it succeeds a moment later (log noise only).

### Not a problem (checked)
- `src/index.ts` contains no DB queries to optimise; it is a bootstrap file. Query-bearing hot spots by count: `services/admin.ts` (74), `routes/admin.ts` (69), `handlers/session.ts` (57), `services/loans.ts` (43).
- Index coverage is adequate for the queries in the scheduler and admin routes reviewed.
- Backups in git contain synthetic data only (verified by inspection).
- Topup idempotency works: the `JournalEntry.txRef` unique-constraint error seen in test output is the duplicate-credit guard firing, followed by `[topup] duplicate credit blocked`. Noisy, correct.
